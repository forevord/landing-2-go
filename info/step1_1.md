# Step 1 — Инициализация проекта

**Фаза:** Setup
**Зависит от:** ничего (первый шаг)
**Блокирует:** все последующие шаги

---

## Цель

Рабочий, задеплоенный скелет проекта, на который будут наслаиваться все остальные шаги. Пустой сайт, доступный по реальному URL — уже с первого дня.

## Контекст из SPEC.md

Раздел 9 (Tech Notes): рекомендованный стек — Next.js + TypeScript + Tailwind CSS + shadcn/ui, обоснование — SSR/SSG для SEO, файловая маршрутизация под i18n, компонентный подход.

## Что делать

1. **Инициализация Next.js**
   - Next.js последней стабильной версии, App Router (не Pages Router — он не подходит под i18n-архитектуру Step 2).
   - TypeScript сразу, без миграции позже (`strict: true` в `tsconfig.json`).

2. **Стилизация**
   - Установить и настроить Tailwind CSS.
   - Инициализировать shadcn/ui (`components.json`, базовая тема) — но без наполнения компонентами, это Step 3.

3. **Качество кода**
   - ESLint (`eslint-config-next` + правила для TypeScript).
   - Prettier с единым конфигом (`.prettierrc`), интеграция с ESLint, чтобы не было конфликтов правил.
   - При соло-разработке это заменяет code review — не пропускать.

4. **Git и репозиторий**
   - Инициализировать репозиторий, если ещё не создан.
   - `.gitignore` (стандартный Next.js + `.env*`, кроме `.env.example`).
   - `README.md` с инструкцией: `npm install`, `npm run dev`, ссылка на SPEC.md и на индекс steps.

5. **Деплой с первого дня**
   - Подключить хостинг (рекомендуется Vercel — нативная поддержка Next.js SSR/SSG без доп. конфигурации).
   - Задеплоить пустой проект, получить рабочий preview-URL.
   - Настроить автодеплой по push в основную ветку.

6. **Переменные окружения (заготовка)**
   - Завести `.env.example` с плейсхолдерами под будущие переменные (адрес получателя заявок, ключи форм-сервиса и т.д. — появятся в Step 5, но файл завести сейчас).

## Структура папок (базовая, будет расти)

```
/app
/components   (пусто, наполнится в Step 3)
/lib          (утилиты, пусто)
/public
.env.example
.eslintrc
.prettierrc
tailwind.config.ts
tsconfig.json
```

## Критерий готовности (Definition of Done)

- [ ] `npm run dev` запускается без ошибок.
- [ ] `npm run build` проходит без ошибок и предупреждений TypeScript/ESLint.
- [ ] Проект задеплоен, preview-URL открывается в браузере (пустая страница — это нормально).
- [ ] Git-репозиторий содержит первый коммит с README.
- [ ] Прогон `npm run lint` и `npm run format` (или эквивалент) настроен и работает.

## Почему этот шаг первый

Без деплой-пайплайна каждый следующий шаг проверяется только локально — расхождения с продакшн-окружением (переменные, сборка, edge-кейсы хостинга) накапливаются незаметно и всплывают в самый неудобный момент, перед релизом.
