# Step 3 — Дизайн-система (основа)

**Фаза:** Setup
**Зависит от:** Step 1
**Блокирует:** Step 4 (компоненты страницы переиспользуют эти primitives)

---

## Цель

Зафиксированные визуальные токены (цвет, типографика, отступы) и набор базовых UI-primitives, чтобы каждый блок страницы в Step 4 собирался из готовых кубиков, а не переизобретал кнопку или инпут заново.

## Контекст из SPEC.md

Раздел 8 (UI Basics): современный премиальный минимализм, industrial-акценты, палитра Primary/Accent/Neutral/Background/Surface/Success/Error, одна гротескная гарнитура. Раздел 7: mobile-first, requirement на достаточный контраст (готовит почву для Accessibility в Step 8).

## Что делать

1. **Цветовые токены**
   - Перевести черновую палитру из SPEC §8 в конкретные HEX/HSL значения и зафиксировать как CSS-переменные или Tailwind `theme.extend.colors`.
   - Primary: тёмный графит/антрацит.
   - Accent: один яркий, высококонтрастный цвет — используется **только** для CTA-элементов (кнопка заявки, submit формы), нигде больше — иначе теряет сигнальную функцию.
   - Neutral-шкала (5–7 оттенков серого) для фона/текста/бордеров.
   - Success/Error — для валидации формы (Step 5).
   - Проверить контраст пар текст/фон на соответствие WCAG AA уже на этом этапе (не откладывать до Step 8 — дешевле поправить токен, чем каждое место использования).

2. **Типографика**
   - Одна гротескная гарнитура (подключить через `next/font` для оптимизации загрузки — важно для Step 7 Performance).
   - Шкала размеров: минимум отдельные значения для H1/H2/H3/body/small, с адаптацией под мобильный/десктоп (например через `clamp()` или Tailwind `text-*` responsive-варианты).

3. **Базовые primitives через shadcn/ui**
   - Button (с вариантами: primary/accent — для CTA, secondary, ghost).
   - Input, Select, Textarea, Checkbox — понадобятся напрямую в форме (Step 5).
   - Accordion — понадобится для FAQ (Step 4).
   - Убедиться, что все primitives уже используют цветовые токены из пункта 1, а не дефолтные цвета shadcn.

4. **Layout-примитивы**
   - Контейнер с максимальной шириной и отступами (переиспользуется в каждом блоке страницы).
   - Breakpoints под mobile-first: явно зафиксировать значения (например `sm/md/lg/xl`), которыми будут пользоваться все блоки Step 4 — не подбирать breakpoints индивидуально в каждом компоненте.

## Критерий готовности

- [ ] Цветовые токены заведены в одном месте (Tailwind config или CSS-переменные), нигде в проекте нет «сырых» HEX-значений вне этого файла.
- [ ] Accent-цвет используется в дизайн-системе с пометкой «только для CTA» (закреплено в README компонентов или комментарии).
- [ ] Шрифт подключен через `next/font`, шкала размеров работает на тестовой странице на всех breakpoints.
- [ ] Button, Input, Select, Textarea, Checkbox, Accordion собраны и визуально соответствуют палитре.
- [ ] Контраст текст/фон проверен инструментом (например DevTools или axe) для основных пар токенов.

## Почему до компонентов страницы

Каждый блок Step 4 использует кнопки, инпуты, отступы. Если primitives не готовы заранее, разработчик либо блокируется на середине блока, либо создаёт одноразовые стили, которые потом придётся сводить к единой системе — дороже, чем сделать один раз здесь.
